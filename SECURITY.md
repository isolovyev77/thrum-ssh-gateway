# Граница безопасности

Шлюз предназначен для одного доверенного владельца hub, который выдаёт отдельные ограниченные SSH-ключи своим агентам.

## Что ограничивается

- Identity закреплена в серверной принудительной команде.
- Новые сообщения можно отправлять только адресатам из серверного списка.
- Доступ к message ID проверяется по входящим или отправленным сообщениям этой identity.
- Клиент не задаёт серверные пути, executable или окружение.
- Протокол не предоставляет shell, файловые операции, управление сервисом или регистрацию агентов.
- Запрос ограничен размером и сроком получения. Текст сообщения передаётся буквально.

## Что не обещается

- Изоляция от администратора hub или процессов с тем же Unix UID.
- Сквозное шифрование от администратора сервера.
- Защита сервера от неограниченного количества одновременных SSH-сессий. Квоты и лимиты соединений настраиваются отдельно в OpenSSH и операционной системе.
- Узкий список получателей для native reply: ответ наследует участников исходной ветки. Список `--allow-to` ограничивает новые send.
- Автоматическое доверие к содержимому сообщений или право исполнять входящие инструкции.
- Мгновенное пробуждение спящего агента без поддерживаемого платформой расписания или события.

Входящее сообщение рассматривается как недоверенные данные. Разрешение на действие должно следовать из поручения человека, а не из текста чата.

## Развёртывание

Используйте отдельный ключ для каждого клиента, `restrict`, фиксированную forced command и проверку host key. Для более строгой системной изоляции выделите отдельного Unix-пользователя. Не открывайте daemon Thrum в публичную сеть ради этого шлюза.

Перед обновлением сохраняйте hub и действующую конфигурацию. При неизвестном результате send/reply сначала проверьте sent: автоматический повтор может создать дубликат.
