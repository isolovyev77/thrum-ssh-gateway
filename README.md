# Thrum SSH Gateway

Небольшой шлюз на стандартной библиотеке Python для ограниченного доступа агента к общему [Thrum](https://github.com/leonletto/thrum) inbox через SSH.

Закрытый ключ остаётся на клиенте. Принудительная серверная команда закрепляет identity и список разрешённых адресатов. Клиент читает свой inbox, отвечает, отмечает прочитанное и ожидает новые сообщения. Он не может выбирать чужую identity, выполнять shell-команды или передавать путь к файлу на сервере.

Это независимая интеграция, не официальный продукт Thrum, OpenAI или Manus.

## Требования

- Python 3.9 или новее на клиенте и сервере.
- Сервер на macOS или Linux с Unix socket и POSIX-сигналами.
- OpenSSH, отдельный ключ и проверенный ключ сервера.
- Работающий Thrum hub; проверенная версия 0.10.6.
- Зарегистрированная серверная identity и явный список разрешённых адресатов.

Используется существующий SSH-маршрут. Публичный HTTP listener и ключ API языковой модели не нужны.

## Границы

SSH и события mailbox сами по себе не пробуждают спящего ИИ-агента. Нужны штатное расписание платформы или активное ограниченное ожидание. Проверка раз в пять минут является опросом, а не мгновенным push.

Шлюз ограничивает возможности отдельного SSH-ключа на уровне приложения. Он не изолирует Unix-аккаунт от администратора или других процессов того же пользователя. Для более строгой системной изоляции используйте отдельный Unix-аккаунт.

Содержимое сообщений недоверенное. Входящее сообщение не даёт разрешения удалять файлы, публиковать материалы, тратить деньги или писать третьим лицам.

Протокол, настройка SSH и ограничения видимости истории описаны в `docs/restricted-access.md`.

## Разработка

```sh
python3 -m unittest discover -s tests -v
```

Интеграционные тесты требуют явного `AGENT_CHAT_RESTRICTED_THRUM_BINARY` с путём к проверенному Thrum binary. Без него они пропускаются, что не считается успешной интеграционной проверкой.
